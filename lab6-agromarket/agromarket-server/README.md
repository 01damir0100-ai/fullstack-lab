# АгроМаркет API

## Запуск
1. Установить PostgreSQL, создать базу `agromarket`
2. Скопировать `.env.example` в `.env` и указать свой пароль
3. `npm install`
4. `npm run db:init` # создать таблицы и загрузить товары
5. `npm run dev` # http://localhost:3000

## Эндпоинты

| Метод | Путь | Описание | Ответы |
|--------|----------------------|--------------------------|---------------|
| GET | /api/health | сервер и связь с БД | 200 |
| GET | /api/products | товары, ?search= | 200 |
| GET | /api/products/:id | один товар | 200, 400, 404 |
| POST | /api/products | создать товар | 201, 400 |
| PUT | /api/products/:id | изменить товар | 200, 400, 404 |
| DELETE | /api/products/:id | удалить товар | 204, 404 |
| GET | /api/orders | заявки + название товара | 200 |
| POST | /api/orders | новая заявка | 201, 400 |
| PATCH | /api/orders/:id | сменить статус заявки | 200, 400, 404 |

Тесты: коллекция `postman/agromarket.postman_collection.json`

## Лабораторная 6 — ответы

- **Ошибки из части 2.**
  `price = -5` — `new row for relation "products" violates check constraint "products_price_check"`, сработало `CHECK (price >= 0)`.
  Без названия — `null value in column "name" of relation "products" violates not-null constraint`, сработало `NOT NULL`.
  Заявка с `product_id = 9999` — `insert or update on table "orders" violates foreign key constraint "orders_product_id_fkey"`, сработал внешний ключ.
- **SQL-инъекция.** С конкатенацией строки `zzz' OR 1=1 --` вернул все товары (условие `OR 1=1` всегда истинно, остаток запроса стал комментарием). Одна кавычка `'` ломает запрос: синтаксическая ошибка SQL, ответ 500, текст ошибки в терминале сервера. С параметром `$1` оба адреса безопасны: `zzz' OR 1=1 --` вернул пустой массив `[]`, одна кавычка тоже `[]`, статус 200, потому что значение подставляется как данные, а не как часть SQL.
- **Двойная защита quantity.** Без JS-проверки `quantity: 5` всё равно не сохраняется: база отклоняет строку по `CHECK (quantity >= 10)`, а `errorHandler` превращает ошибку 23514 в ответ 400 «Значение не проходит проверку в БД». JS-проверка нужна, чтобы дать пользователю понятное сообщение («Минимальный объём заказа — 10 кг»), не обращаясь к базе. CHECK нужен как последняя линия защиты: если кто-то запишет данные в обход API (другой сервис, ручной SQL), база не пропустит плохую строку.
- **Заявка с `product_id: 9999`.** Ответ 400 «Связанная запись не найдена» сформировал `errorHandler` по коду PostgreSQL 23503 (нарушение внешнего ключа).
- **Что стало с заявкой после удаления товара.** Заявка осталась в `/api/orders`, но `product_id` стал `null`, а `product_name` тоже `null`: сработал `ON DELETE SET NULL`, а `LEFT JOIN` не потерял заявку.
