# АгроМаркет API

## Запуск
1. Установить PostgreSQL, создать базу `agromarket`
2. Скопировать `.env.example` в `.env`, указать пароль базы, свой `JWT_SECRET` и пароль администратора
3. `npm install`
4. `npm run db:init` # создать таблицы, загрузить товары, создать администратора
5. `npm run dev` # http://localhost:3000

## Переменные окружения (.env)
- `JWT_SECRET` — случайная строка 64 символа: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- `JWT_EXPIRES_IN` — срок жизни токена, например `2h`
- `ADMIN_EMAIL` / `ADMIN_PASSWORD` — администратор, создаётся командой `npm run db:init`

## Продакшен

- Сайт: https://agromarket-01damir0100-ai.vercel.app
- API: https://agromarket-api-01damir0100-ai.onrender.com/api/health
- Схема: React (Vercel) → Express (Render, Frankfurt) → PostgreSQL (Neon, Frankfurt)

### Как происходит деплой

1. Изменения — только через Pull Request: CI + ревью
2. Merge в main → CI: test → deploy (Render deploy hook, ref = SHA) → smoke
3. React собирается Vercel из main автоматически
4. Авария: Rollback на Render, затем git revert через PR

## Тестирование
1. Создать базу `agromarket_test` (pgAdmin или psql)
2. Скопировать `.env.test.example` в `.env.test` и указать пароль от PostgreSQL
3. `npm test` — все тесты, `npm run test:watch` — режим наблюдения,
   `npm run coverage` — отчёт о покрытии (сейчас: Lines ЗАПОЛНИТЕ%)

Тесты работают только с базой `agromarket_test`: `tests/globalSetup.js` прерывает запуск, если в настройках подключения нет слова `test`.

Одна кавычка `'` ломает запрос: синтаксическая ошибка SQL, ответ 500. С параметром `$1` оба адреса безопасны: `[]` и статус 200, потому что значение подставляется как данные, а не как часть SQL.

JS-проверка даёт понятное сообщение без обращения к базе, а CHECK — последняя линия защиты, если данные пишут в обход API.
- **Заявка с `product_id: 9999`.** Ответ 400 «Связанная запись не найдена» сформировал `errorHandler` по коду PostgreSQL 23503.
- **Удаление товара.** Заявка осталась, `product_id` и `product_name` стали `null` (`ON DELETE SET NULL` и `LEFT JOIN`).

## Лабораторная 7 — ответы

- **Хэши у двух пользователей с одним паролем.** Разные: bcrypt добавляет к паролю случайную соль и хранит её внутри хэша. По базе нельзя понять, что пароли одинаковы, и не работают заранее посчитанные таблицы «пароль → хэш».
- **Регистрация с `"role": "admin"`.** Сервер вернул 201 и роль `user`: поле `role` из тела запроса не читается, роль ставит `DEFAULT 'user'` в базе. Так мы защищены от mass assignment.
- **Подделанный токен.** Подпись считается от заголовка и данных с секретным ключом `JWT_SECRET`. После замены `role` на `admin` старая подпись больше не сходится с данными, а новую без ключа не посчитать, поэтому `jwt.verify` бросает исключение и сервер отвечает 401 «Недействительный токен».
- **Порча токена в localStorage.** При открытии страницы React вызывает `/auth/me`, сервер отвечает 401, функция `apiFetch` удаляет `token` и `user` из localStorage и перезагружает страницу: форма входа появляется снова.
- **Почему мало спрятать кнопку в React.** Скрытие формы меняет только интерфейс, а запрос можно отправить в обход него (DevTools, curl, Postman). Настоящая защита на сервере: `requireAuth` и `requireRole('admin')` вернули 403 обычному пользователю даже при запросе из консоли.
- **Использовал(а) ли ИИ и для чего:** ЗАПОЛНИТЕ САМИ
